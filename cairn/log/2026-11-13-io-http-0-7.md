# io-http 0.7

The crate moves from io-http 0.6 to 0.7.0, and its dev-dependency io-oauth from 0.5 to 0.6.0, itself on io-http 0.7, so a single io-http resolves in the graph. Nothing under src/, tests/ or examples/ had to change: the crate builds requests as `HttpRequest` values and hands them to `Http11Send::new`, which stays infallible, and it never called `to_http_11_vec`, the event stream parser or the `Display` of `HttpAuthBearer`.

Breaking for consumers all the same: the coroutines take and yield io-http types (`HttpRequest`, `HttpResponse`, the credentials, `Http11SendError`), so a consumer moves in step.

What the HTTP layer now does under the coroutines, unchanged code:

- A method or a header name that is not a token, a header value holding CR, LF or NUL, and a `Transfer-Encoding` request header fail the first resume with `Http11SendError::InvalidRequest`, nothing written. It reaches a caller as `WebdavSendError::Send` or `WebdavFollowRedirectsError::Send`.
- Interim 1xx responses are skipped, up to 8, then `TooManyInterimResponses`.
- Chunk data without its CRLF fails, trailers are read and dropped, and a final transfer coding other than `chunked` fails with `UnsupportedTransferCoding`.
- An HTTP/1.0 response keeps the connection only on the `keep-alive` option, and a body read to EOF never does.

The header value check of the-request-boundary stays in `WebdavSendRaw::new` and `WebdavFollowRedirects::new`. It runs before `Http11Send` is built and refuses more: every byte below 0x20 and 0x7F, a tab included, where io-http refuses CR, LF and NUL. A request carrying one still completes with `InvalidHeader`, as the two tests of that change assert against 0.7.

No scripted test pinned a behaviour 0.7 changed: no fixture carries a chunked body, an interim response or an HTTP/1.0 status line, and none was edited. tests/google.rs compiles unchanged against the JWT bearer client of io-oauth 0.6; a refusal without an OAuth error body now ends its `expect` on the `Status` error instead of a parse error.

Verified: offline suite green over all features, clippy with `-D warnings` clean, `--no-default-features` build clean, `cargo publish --dry-run` packaging against the registry. The live suites were compiled and not run.

No capability moved.
